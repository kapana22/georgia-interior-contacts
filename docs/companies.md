# კომპანიების ბაზა

გვერდი: `/companies/`. საწყისი Excel-ის ყველა 16 ველი ინახება `web/companies/data.json`-ში, წყაროს სახელითა და სტრიქონის ნომრით. ფაილის საქმიანობის კატეგორიები არ არსებობს: სახელში მკაფიო სიტყვები მხოლოდ **გადასამოწმებელ** მიმართულებას ქმნის. დეველოპმენტი ნიშნავს უძრავი ქონების დეველოპმენტის კანდიდატებს; ტექნოლოგიის აშკარა ნიშნები ცალკე გადის. სახელით ვერ გამოვლენილი კომპანიები დაუზუსტებელი რჩება.

ქალაქის ფილტრში ერთიანდება გავრცელებული ჩაწერის ვარიანტები; რამდენიმე ქალაქის შემთხვევაში გამოიყენება პირველი მითითებული ქალაქი. ორიგინალური ქალაქის ველი სრულად ინახება.

ძიება, მიმართულება, ქალაქი და კონტაქტი ერთად ფილტრავს მონაცემებს. მიმართულებების ღილაკებზე ჩანს მთლიანი ბაზის რაოდენობები. სტატუსებითა და წყაროებით დაყოფა ინტერფეისიდან ამოღებულია. CSV შეიცავს მხოლოდ გაფილტრულ შედეგებს. სრული JSON ასლი ყველა კომპანიას შეიცავს.

## დამატება და შესწორება

„+ კომპანია“ ამატებს ჩანაწერს. ბარათის ღილაკით შეიძლება ყველა ველის და მიმართულების შეცვლა. შენიშვნა არასავალდებულოა.

ცვლილებები ინახება IndexedDB-ში **ამ ბრაუზერისთვის**. ეს ჯერ არ არის მომხმარებლებს შორის საერთო სერვერული ბაზა. ბრაუზერის მონაცემების წაშლამდე ჩამოტვირთეთ სრული JSON ასლი; სხვა ბრაუზერში მისი იმპორტი შესაძლებელია. საწყისი მონაცემები ადგილობრივ შესწორებებს არ გადაწერს.

## სკრაპერის შედეგების დამატება

„JSON-ის დამატება“ იღებს `{ "records": [...] }` ან ჩანაწერების მასივს. არსებული სკრაპერების `facts`-იდან გადადის phone/email/website/city/address; წყაროები შენარჩუნებულია evidence-ში. თითო კომპანიას სჭირდება სტაბილური `id`, `name` და, როცა ცნობილია, `tax_id`. დამატებითი ველები შეესაბამება `web/companies/core.js`-ის fields სიას.

სანდო მიმართულებისთვის მიუთითეთ `category` (`development`, `construction`, `architecture`, `interior`, `technology`, `other`, `unknown`), `classification_status` (`candidate` ან `confirmed`) და `category_evidence`. სკრაპერის ზოგადი categories მასივი ავტომატურად დადასტურებულ საქმიანობად არ ითვლება.

განახლება ემთხვევა სტაბილურ ჩანაწერის ID-ს ან უნიკალურ ID კოდს; სახელი/საერთო ტელეფონი კომპანიებს არ აერთიანებს. ორაზროვანი ID კოდი იმპორტს აჩერებს. ცარიელი შემოსული ველები არსებულ კონტაქტებს არ შლის. განსხვავებული ID-ებითა და ID კოდის გარეშე შემოსული კომპანია ცალკე რჩება. ეს ფუნქცია შენახულ შედეგებს ამატებს; ახალი დეველოპერული წყაროების ინტერნეტიდან შეგროვება ცალკე სკრაპერის გამართვას საჭიროებს.

Excel-ის ხელახალი გადატანა (ბრაუზერის შესწორებებს არ ცვლის):

```sh
python3 scripts/import_companies.py /absolute/path/companies.xlsx
npm run dev
```

იმპორტერი მხოლოდ კითხულობს Excel-ს, ამოწმებს 16 სათაურს და ID-ების უნიკალურობას, შემდეგ ატომურად ინახავს JSON-ს. საწყის Excel-ს არ ცვლის. სტატიკური build მოიცავს კომპანიების მონაცემებს.

## ერთიანი ინტერფეისი და ჩამოტვირთვა

მთავარი გვერდი ხსნის ერთიან ბაზას. ძველი ცალკე მენიუს ნაცვლად „აუდიტორია“ ფილტრი აერთიანებს ინტერიერის კონტაქტებს და ვებსაიტის პოტენციურ კლიენტებს (ვებსაიტი არ არის მითითებული და კონტაქტი არსებობს). მიმართულებების რაოდენობები მთელ ბაზას ეხება; შედეგების რაოდენობა ყველა აქტიურ ფილტრს ითვალისწინებს. ერთ კომპანიას შეიძლება რამდენიმე მიმართულება ჰქონდეს, ამიტომ მიმართულებების ჯამი უნიკალური კომპანიების რაოდენობას შეიძლება აღემატებოდეს.

ხელმისაწვდომია ცხრილი და ბარათები, სახელით/ქალაქით დალაგება, 30/50/100 ჩანაწერი გვერდზე და კომპანიების მონიშვნა. მონიშვნა ფილტრების შეცვლისას შენარჩუნდება. ჩამოტვირთვის საწყისი არჩევანი **აქტიური ფილტრების შედეგებია**; სხვა არჩევანია მონიშნული კომპანიები ან მთელი ბაზა. ფორმატები: კონტაქტების CSV, ყველა ველის CSV, სრული JSON. ფაილის სახელი შეიცავს მოცულობას და თარიღს. ცალკე სტატუსები და წყაროების ფილტრი აღარ ჩანს.

## ბაზის გაზრდა

პირველი ორი კატეგორიის კონფიგურაცია: `config/companies-sources.json` (დეველოპმენტი და მშენებლობა). გაშვება იზოლირებულ მდგომარეობას იყენებს და ინტერიერისა და ვებსაიტის კლიენტების პროცესებს არ ცვლის:

```sh
python -m georgia_leads.cli --sources config/companies-sources.json --state .leads-state/companies.json --output output/companies-growth --limit 1000 --max-minutes 2
node scripts/merge_companies.mjs output/companies-growth/snapshot.json
npm run build
```

საჯარო ინტერიერის ექსპორტისთვის იგივე merge ბრძანებას დაამატეთ მეორე არგუმენტი `interior`. სხვა ექსპორტები იღებს `general` რეჟიმს (საწყისი მნიშვნელობა). გაერთიანება ეყრდნობა ID-ს, უნიკალურ საიდენტიფიკაციო კოდს, ან ერთდროულად სახელისა და კონტაქტის დამთხვევას. მხოლოდ საერთო ტელეფონი კომპანიებს არ აერთიანებს. არსებული იურიდიული მონაცემები ინახება; შპს-ს სტატუსი არ გამოიცნობა. განმეორებით დამატება ახალ დუბლიკატებს არ ქმნის. ახალი კატეგორიები დაემატება კონფიგურაციაში შესაფერისი კატალოგის არჩევის შემდეგ. ავტომატური განრიგი ჩართული არ არის.
