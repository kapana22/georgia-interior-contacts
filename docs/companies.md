## დამატება და შესწორება

„+ კომპანია“ ამატებს ჩანაწერს. ბარათის ღილაკით შეიძლება ყველა ველის და მიმართულების შეცვლა. შენიშვნა არასავალდებულოა.

ცვლილებები ინახება IndexedDB-ში **ამ ბრაუზერისთვის**. ეს ჯერ არ არის მომხმარებლებს შორის საერთო სერვერული ბაზა. ბრაუზერის მონაცემების წაშლამდე ჩამოტვირთეთ სრული JSON ასლი; სხვა ბრაუზერში მისი იმპორტი შესაძლებელია. საწყისი მონაცემები ადგილობრივ შესწორებებს არ გადაწერს.

## სკრაპერის შედეგების დამატება

„JSON-ის დამატება“ იღებს `{ "records": [...] }` ან ჩანაწერების მასივს. არსებული სკრაპერების `facts`-იდან გადადის phone/email/website/city/address; წყაროები შენარჩუნებულია evidence-ში. თითო კომპანიას სჭირდება სტაბილური `id`, `name` და, როცა ცნობილია, `tax_id`. დამატებითი ველები შეესაბამება `web/companies/core.js`-ის fields სიას.

სანდო მიმართულებისთვის მიუთითეთ `category` (`development`, `construction`, `architecture`, `interior`, `technology`, `other`, `unknown`), `classification_status` (`candidate` ან `confirmed`) და `category_evidence`. სკრაპერის ზოგადი categories მასივი ავტომატურად დადასტურებულ საქმიანობად არ ითვლება.

განახლება ემთხვევა სტაბილურ ჩანაწერის ID-ს ან უნიკალურ ID კოდს; სახელი/საერთო ტელეფონი კომპანიებს არ აერთიანებს. ორაზროვანი ID კოდი იმპორტს აჩერებს. ცარიელი შემოსული ველები არსებულ კონტაქტებს არ შლის. განსხვავებული ID-ებითა და ID კოდის გარეშე შემოსული კომპანია ცალკე რჩება. ეს ფუნქცია შენახულ შედეგებს ამატებს; ახალი დეველოპერული წყაროების ინტერნეტიდან შეგროვება ცალკე სკრაპერის გამართვას საჭიროებს.

Excel-ის ხელახალი გადატანა (ბრაუზერის შესწორებებს არ ცვლის):

```sh
python3 scripts/import_companies.py /absolute/path/companies.xlsx
npm run dev
```

იმპორტერი მხოლოდ კითხულობს Excel-ს, ამოწმებს 16 სათაურს და ID-ების უნიკალურობას, შემდეგ ატომურად ინახავს JSON-ს. საწყის Excel-ს არ ცვლის. სტატიკური build მოიცავს კომპანიების მონაცემებს.

## ერთიანი ინტერფეისი და ჩამოტვირთვა

მთავარი გვერდი ხსნის ერთიან ბაზას. ძველი ცალკე მენიუს ნაცვლად „აუდიტორია“ ფილტრი აერთიანებს ინტერიერის კონტაქტებს და ვებსაიტის პოტენციურ კლიენტებს (ვებსაიტი არ არის მითითებული და კონტაქტი არსებობს). მიმართულებების რაოდენობები მთელ ბაზას ეხება; შედეგების რაოდენობა ყველა აქტიურ ფილტრს ითვალისწინებს. ერთ კომპანიას შეიძლება რამდენიმე მიმართულება ჰქონდეს, ამიტომ მიმართულებების ჯამი უნიკალური კომპანიების რაოდენობას შეიძლება აღემატებოდეს.

ხელმისაწვდომია ცხრილი და ბარათები, სახელით/ქალაქით დალაგება, 30/50/100 ჩანაწერი გვერდზე და კომპანიების მონიშვნა. მონიშვნა ფილტრების შეცვლისას შენარჩუნდება. ჩამოტვირთვის საწყისი არჩევანი **აქტიური ფილტრების შედეგებია**; სხვა არჩევანია მონიშნული კომპანიები ან მთელი ბაზა. ფორმატები: კონტაქტების CSV, ყველა ველის CSV, სრული JSON. ფაილის სახელი შეიცავს მოცულობას და თარიღს. ცალკე სტატუსები და წყაროების ფილტრი აღარ ჩანს.

ყველა ფილტრი მრავალარჩევითია: მიმართულება, ქალაქი, კონტაქტი, აუდიტორია, იურიდიული ფორმა, ქვეყანა, როლი, რეგისტრაციის წელი, აქტიური ტენდერი, საკონტაქტო პირი, ვებსაიტი და სოციალური პროფილები. ერთ ჯგუფში არჩევანი ერთიანდება, სხვადასხვა ჯგუფი ერთად მოქმედებს. ცარიელი მონაცემი ცალკე „არ არის მითითებული“ ვარიანტია და არ ითვლება უარყოფით პასუხად ტენდერებზე. რეგისტრაციის წელი წყაროს რეგისტრაციის ველიდან მოდის. არჩეული ფილტრები ჩამოტვირთვაშიც მოქმედებს.

კომპანიების კატალოგის შეგროვებისას გამოიყენეთ `--directory-only`, რათა შეინახოს საიტებისა და სოციალური პროფილების ბმულები მათი დამატებითი შემოწმების გარეშე. პროცესი თითო გაშვებაზე მაქსიმუმ ხუთ კატალოგის გვერდს ამუშავებს; იგივე ბრძანების გამეორება დარჩენილ რიგს აგრძელებს. `--restart` საჭიროა მხოლოდ კატალოგის თავიდან წასაკითხად. გვერდების მისამართები მიიღება გამოქვეყნებული გვერდის ღილაკებიდან და იმავე კატეგორიის ფორმიდან; სხვა კატეგორიაზე მცდარი JSON-LD ბმული არ გამოიყენება.

## დამატებითი დეველოპერული კატალოგი

`python scripts/collect_developers.py --max-minutes 10 --profiles 40` კითხულობს Saxlebi.com-ის საჯარო დეველოპერების სიას, შემდეგ მითითებული რაოდენობის პროფილებს. შემდეგი გაშვება შენახული რიგიდან გრძელდება; გრაფიკი ან ფონური მომსახურება ავტომატურად არ იქმნება. მისამართები მოდის რეალური ბმულებიდან, დაცულია robots.txt, მოთხოვნებს შორის მინიმუმ 2 წამი და დროის ლიმიტი. შეცდომა და დაუმთავრებელი რიგი ინახება `.leads-state/developers-saxlebi.json`-ში.

იმპორტი: `node scripts/merge_companies.mjs output/companies-growth/developers-saxlebi.json catalog`. კატალოგის რეჟიმი სახელის დამთხვევისას, როცა ID/კონტაქტით დამთხვევა არ არის, ჩანაწერს ინახავს `*.deferred.json`-ში და საერთო რაოდენობას არ უმატებს. წყაროს სტაბილური ID-ები ხელახალ იმპორტზეც ემთხვევა. მხოლოდ საჯარო სახელი არ ადასტურებს შპს-ს იურიდიულ ფორმას; ველი დაუზუსტებელი რჩება. პროფილის კონტაქტები დაემატება მათი წაკითხვის შემდეგ; ჩამონათვალში არსებული კომპანია შესაძლოა ჯერ კონტაქტის გარეშე იყოს. დაარსების წელი რეგისტრაციის თარიღად არ გარდაიქმნება.

## ავტომატური შეგროვება — GitHub Actions

`Grow company directory` (`.github/workflows/companies.yml`) ჩართულია: დარჩენილი სამუშაო პარტიის დასრულების შემდეგ ავტომატურად აგრძელებს შემდეგ პარტიას. დამატებითი განრიგი ყოველ საათში 17-ე და 47-ე წუთზე აღადგენს შეწყვეტილ პროცესს. ერთი პარტია მაქსიმუმ 18 წუთია; თავად შეგროვება 8 წუთამდე დეველოპერებზე და 2 წუთამდე Yell-ზე. ეს არის მთელი დღე მოქმედი ავტომატიზაცია და არა უწყვეტი სერვერი: GitHub-ის რიგმა ან წყაროს cooldown-მა შეიძლება გააჩინოს პაუზა.

პროგრესი, დუბლიკატის შესაძლო დამთხვევები და მონაცემები ინახება `companies-data` ბრენჩში, ძირითადი კოდისგან დამოუკიდებლად. საიტი ამ ბრენჩის `data.json`-ს კითხულობს; მიუწვდომლობისას იყენებს დეფლოიში შენახულ ასლს. ყოველი გვერდის/პროფილის შემდეგ ინახება ადგილობრივი checkpoint, პარტიის ბოლოს — სერვერული. ძველი მონაცემები არ იშლება. ერთი პროცესი მუშაობს ერთდროულად; ჩაშლისას შემდეგი გაშვება შენახული პროგრესიდან იწყებს.

ამოწურული კატალოგები ყოველდღე ხელახლა იკითხება; უკვე შეგროვებული პროფილები — ყოველ კვირას. 429 და სხვა ბლოკირებისას წყაროს მოთხოვნილი პაუზა ინახება. სამუშაოს ამოწურვისას პროცესი ელოდება შემდეგ განახლებას. ახალი სფეროები ავტომატურად არ ემატება: მიმდინარე კონფიგურაცია დეველოპმენტსა და მშენებლობას მოიცავს.

ხელით დაწყება: `gh workflow run companies.yml`. შეჩერება: `gh workflow disable companies.yml`, შემდეგ მიმდინარე გაშვების გაუქმება Actions-იდან. სამუშაო სტატუსი და დარჩენილი პროფილები ჩანს workflow-ის Summary-ში და `companies-data/report.json`-ში. ახალი ტესტის გაშვების ნაბიჯი ამ workflow-ში არ არის.

## B2B მიზანი და ავტომატური პაუზა

`companies.yml` იღებს `b2b_target` რიცხვს და `b2b_mode` არჩევანს (`new` ან `existing`). კამპანიის პარამეტრები პირველად ინახება `companies-data/campaign.json`-ში. `new` გამორიცხავს დაწყებისას არსებულ კომპანიებს; `existing` არსებულ მომწოდებლებსაც ითვლის. ითვლება მხოლოდ ტელეფონით ან ელფოსტით მქონე B2B ჩანაწერები, რომელთა საქმიანობა წყაროს როლით ან კატალოგითაა დასაბუთებული. უპირატესობა ენიჭება საიდენტიფიკაციო კოდის მქონე შპს/სს-ს. ერთი საიდენტიფიკაციო კოდი ერთი კომპანიაა; ცალკეული თანამშრომლები რაოდენობას არ ზრდის. ეს არ ადასტურებს შემოსავალს ან კონტაქტის მოქმედებას.

არჩეული სია ინახება `b2b-target.json` და Excel-თან თავსებად `b2b-target.csv` ფაილებში, იმავე data ბრენჩზე. მიღწევისას `report.json` შეიცავს `b2b_campaign.paused=true`; `automatic=false`, `work_ready=false`. შემდეგ workflow ითიშება, ხოლო შემთხვევით უკვე რიგში მყოფი განახლებული გაშვება შეგროვებამდე ამოწმებს მიზანს. ძველი ბაზა და წყაროების პროგრესი შენარჩუნებულია.

## გაფართოება 5 000-იანი სიის შემდეგ

`resume_collection=true` აარქივებს ძველი კამპანიის პაუზას (`campaign.active=false`) და ინახავს პირველ საწყის რაოდენობასა და ID-ებს `growth-baseline.json`-ში. უკვე მომზადებული 5 000-იანი CSV/JSON უცვლელად რჩება. `report.growth` ცალ-ცალკე ითვლის ახლად დამატებულ კომპანიებს, მათ შორის კონტაქტიან კომპანიებს და ბაზაში კონტაქტიან ჩანაწერებს. თვითნებური ახალი რაოდენობრივი პაუზა არ დაწესებულა.

დაემატა 237 კატეგორია (ჯამში 254). მისამართები მიღებულია Yell-ის გამოქვეყნებული კატეგორიების ბმულებიდან: [ფინანსები და სამართალი](https://www.yell.ge/categories.php?lan=geo&nav=4), [სამრეწველო სექტორი](https://www.yell.ge/categories.php?lan=geo&nav=16), [ენერგეტიკა](https://www.yell.ge/categories.php?lan=geo&nav=39), [რეკლამა და პოლიგრაფია](https://www.yell.ge/categories.php?lan=geo&nav=18), [ტექნიკა და მომარაგება](https://www.yell.ge/categories.php?lan=geo&nav=12), [კვების მრეწველობა](https://www.yell.ge/categories.php?lan=geo&nav=11), [მომსახურება](https://www.yell.ge/categories.php?lan=geo&nav=15), [აგროსექტორი](https://www.yell.ge/categories.php?lan=geo&nav=21). განმეორებადი მენიუს ბმულები გამორიცხულია. თითო კატეგორია ინარჩუნებს საკუთარ პროგრესს; `industry` აერთიანებს მას პანელის მსხვილ მიმართულებაში. წყაროს დაყოვნება და მოთხოვნების ლიმიტი უცვლელია.

Companyinfo-ს საჯარო ფორმა და მისივე JavaScript-ში გამოქვეყნებული კომპანიების საძიებო API შემოწმდა, მაგრამ API-მ HTTP 500 დააბრუნა. ამ წყაროდან მონაცემები არ დამატებულა და რაოდენობაში არ ჩათვლილა. რეესტრის ყველა იურიდიული პირი ავტომატურად საკონტაქტო ან მაღალშემოსავლიან B2B კომპანიად არ ითვლება.
