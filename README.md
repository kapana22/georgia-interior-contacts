# georgia-interior-contacts

საქართველოს ინტერიერის დიზაინერებისა და სტუდიების **საჯარო ბიზნესკონტაქტების** განმეორებით შესაგროვებელი Python სკრაპერი. არქიტექტურული კომპანია შესაბამის კანდიდატად ითვლება მხოლოდ ინტერიერის დიზაინის სერვისის ნიშნების არსებობისას. უფასო ბიბლიოთეკები; არ სჭირდება ფასიანი API, პროქსი, AI სერვისი ან სოციალური ქსელის ავტორიზაცია.

**ეს არ არის საქართველოს ყველა დიზაინერის სრული ბაზა.** კონფიგურაციაში 36 რეალური ბიზნესის საიტია. დამატებით, Yell.ge, City24.ge, Dizaini.ge, Homeis.ge, ArchiAward და საჯარო PDF კატალოგი ავტომატურად იკითხება ახალი ბიზნესების აღმოსაჩენად. კონტაქტებს პროგრამა იღებს წყაროებიდან; საწყისი მისამართებისა და წვდომის წესების კვლევა კონტაქტების ხელით შეყვანას არ ნიშნავს. ეს არ არის მთელი ინტერნეტის ავტომატური ძიება. საიტზე ჩანაწერის არსებობა კომპანიის საქმიანობის ან კონტაქტის მოქმედების გარანტია არ არის.

**საჯარო რეპოზიტორიაში `data` ბრენჩზე შენახული კონტაქტები, ისტორია და შედეგებიც საჯაროა.** Artifact-ებიც ხელმისაწვდომია რეპოზიტორიაზე წაკითხვის უფლების მქონე GitHub მომხმარებლისთვის. კოდის MIT ლიცენზია მესამე მხარის მონაცემებზე უფლებებს არ ანიჭებს. შეაგროვეთ მხოლოდ ბიზნესისთვის გამოქვეყნებული კონტაქტები; ნუ დაამატებთ პირად/დახურულ პროფილებს, ავტორიზაციის მონაცემებს ან საიდუმლოებს. მონაცემების გასწორება/წაშლა ადმინისტრატორმა უნდა მართოს; Git ისტორიიდან წაშლა ცალკე მოქმედებაა.

## ინსტალაცია და ლოკალური გაშვება

საჭიროა Python 3.11+ და Git. მხარდაჭერილი გარემო: Linux/macOS; Windows-ზე გამოიყენეთ WSL. ტესტები GitHub Actions-ში Python 3.12-ზე სრულდება.

```bash
git clone https://github.com/kapana22/georgia-interior-contacts.git
cd georgia-interior-contacts
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[test]'
python -m pytest -q
georgia-contacts
```

თუ საქაღალდის გზაში `:` არის, Python ვერ ქმნის იქ venv-ს. ალტერნატივა, იმავე პროექტის საქაღალდიდან:

```bash
python3 -m venv "$HOME/.venvs/georgia-interior-contacts"
source "$HOME/.venvs/georgia-interior-contacts/bin/activate"
python -m pip install -e '.[test]'
```

ერთი მარტივი ბრძანებაა `georgia-contacts`; მოდულის ფორმაც მუშაობს:

```bash
python -m georgia_contacts.cli --limit 50 --sources config/sources.json
```

მცირე, სამი ბიზნესის გამოცდა (კატალოგის მაქსიმუმ ერთი გვერდით):

```bash
georgia-contacts --sources config/smoke.json --limit 3
```

სხვა პარამეტრები:

```bash
georgia-contacts --limit 10 --sources config/sources.json \
  --state .state/state.json --output output --max-minutes 24
georgia-contacts --limit 3 --sources config/smoke.json --no-discovery
```

`--limit` ითვლის **დამუშავებულ ბიზნესებს**, მათ შორის მიუწვდომელ საიტებს; არ არის კონტაქტების ან HTTP მოთხოვნების რაოდენობა. საწყისი ლიმიტი 50-ია (დასაშვები 1–1000). თითო ჰოსტზე მაქსიმუმ 5 კონტენტის მოთხოვნა, გადამისამართებების ჩათვლით; robots.txt და შეზღუდული retry ცალკე მოთხოვნებია. `www.` და მის გარეშე ჰოსტი ერთ ბიზნესად/ლიმიტად ითვლება. განსხვავებული ქვედომენები ავტომატურად არ ერთიანდება.

შემდეგ გაშვებაზე იგივე `--state` გამოიყენეთ. ჯერ დაუმუშავებელი, შემდეგ ყველაზე ადრე მცდელობილი საიტები მუშავდება: პატარა ლიმიტით პირველი 50 წყარო სამუდამოდ არ დაჩრდილავს დანარჩენებს. `config/smoke.json` სრულ სიას არ უშვებს, თუმცა თუ იმავე მდგომარეობაში სხვა კანდიდატები უკვე არის შენახული, რიგში ისინიც მონაწილეობენ. იზოლირებული გამოცდისთვის მიუთითეთ ახალი `--state` და `--output`.

## შედეგები და მონაცემთა მოდელი

ყოველი დასრულებული ბიზნესის შემდეგ მდგომარეობა და ექსპორტები ეტაპობრივად ინახება. მდგომარეობა ატომურად იცვლება დროებითი ფაილისა და `os.replace`-ის გამოყენებით. ლოკალური lock კრძალავს ერთი state-ის ერთდროულ შეცვლას. სხვადასხვა state-ით ერთსა და იმავე output-ში პარალელურად ნუ გაუშვებთ.

| ფაილი | შინაარსი |
|---|---|
| `output/contacts.csv` | თითო გაერთიანებულ ბიზნესზე ერთი მწკრივი; ქართული UTF-8 BOM, Excel-თან თავსებადი |
| `output/contacts.json` | სრული ჩანაწერები, თითო მნიშვნელობის წყარო და თარიღები |
| `output/changes.csv` | `new`, `changed`, `merged`; მიმდინარე გაშვების საწყის მდგომარეობასთან შედარება |
| `output/report.txt` | დამუშავებული საიტები, კონტაქტები, ახალი/შეცვლილი ჩანაწერები და შეცდომები |
| `output/report.json` | სტატისტიკა და თითო URL-ის შედეგი/შეცდომის მიზეზი |
| `.state/state.json` | წინა ჩანაწერები, აღმოჩენილი კანდიდატების რიგი და ბოლო მცდელობები |

`facts` მასივში თითოეულ მნიშვნელობას აქვს `kind`, `value`, `source_url`, `first_seen`, `last_seen` (UTC ISO 8601). ერთსა და იმავე კონტაქტს რამდენიმე წყარო შეიძლება ჰქონდეს. CSV-ის `evidence_json` სვეტი ამავე წყაროებს ინახავს. დაკარგული ველები ცარიელია; JSON-ში შესაბამისი ფაქტი არ იქმნება. ქალაქი მოდის მხოლოდ სტრუქტურირებული მისამართიდან ან მისამართის/კონტაქტის კონტექსტში დაწერილი ქალაქიდან; ნომრითა და ბიზნესის სახელით ქალაქი არ გამოიცნობა. გავრცელებული ქალაქების სახელები ნორმალიზდება, სხვა `addressLocality` უცვლელად ინახება.

`phones` შეიცავს მხოლოდ სტრუქტურულად ვალიდურ ნომრებს. საქართველოს სრული ეროვნული ნომერი/სწორი საერთაშორისო ფორმა გადადის `+995…` ფორმატში; შვიდნიშნა ადგილობრივ ნომერს ქალაქის კოდი არ ემატება. სწორი უცხოური საერთაშორისო ნომერი საკუთარ კოდს ინარჩუნებს. გაურკვეველი `tel:`/JSON-LD ნომერი `phones_unverified`-ში რჩება და ჩანაწერი გადამოწმებას მოითხოვს. სავარაუდო ელფოსტები არ იქმნება; გავრცელებული შაბლონური `example.com`/`mysite.com` მისამართები გამოირიცხება.

სოციალური ბმულები ამოიღება ბიზნესის HTML/JSON-LD-დან. თვითონ Facebook/Instagram პროფილებზე მოთხოვნა არ იგზავნება; ბმულის არსებობა პროფილის მოქმედებას არ ადასტურებს. გაზიარების და შესვლის ბმულები გამოირიცხება. CAPTCHA-ს გადაჭრა, დახურული პროფილები და სურათის OCR არ ხდება. ტექსტური PDF კატალოგები მხარდაჭერილია: წყარო შეიცავს გადამოწმებულ სახელებსა და გვერდების წყვილებს, კოდი კი კონტაქტებს დოკუმენტიდან იღებს. ყველა ასეთი ფაქტი `historical_source: true`-ით და PDF მეტამონაცემის შექმნის თარიღით ინახება; შექმნის თარიღი გამოცემის თარიღად არ ცხადდება. ძველი PDF-ის ტელეფონი/ელფოსტა სამიზნე 1000-ში მხოლოდ სხვა მიმდინარე წყაროში დამოუკიდებლად ნახვის შემდეგ ითვლება.

ფორმულის ინექციისგან დასაცავად საშიში CSV უჯრედები იწყება აპოსტროფით — მათ შორის `+995…` ნომრებიც. პროგრამული დამუშავებისთვის გამოიყენეთ JSON: იქ მნიშვნელობები უცვლელია. CSV არის სტანდარტული მძიმით გამოყოფილი ფაილი; საჭიროებისას Excel-ში გამოიყენეთ **Data → From Text/CSV → UTF-8 → Comma**.

## ხარისხი, დუბლიკატები და ცვლილებები

შესაბამისობა ევრისტიკულია: ქართული/ინგლისური/რუსული ინტერიერის დიზაინის ფრაზები და საქართველოში მუშაობის ნიშნები. `candidate` ნიშნავს ავტომატურად შესაბამის კანდიდატს, **არა ადამიანის მიერ დამოწმებულ ჩანაწერს**. `review` და `review_reasons` აჩვენებს, მაგალითად:

- `interior_service_not_confirmed`: მხოლოდ არქიტექტურა ან ინტერიერის სერვისი ვერ დადასტურდა;
- `georgia_operation_not_confirmed`: საქართველოში საქმიანობის ნიშანი ვერ მოიძებნა;
- `no_contacts_found`, `unverified_phone_structure`, `multiple_cities`;
- `demo_or_fictional_business`, `shared_contact_across_domains`, შერეული სტუდია/აკადემიის კონტაქტები;
- არასრული გვერდების, robots-ის ან სხვა წვდომის პრობლემები.

ერთიანდება ზუსტად იგივე ჰოსტი ან ზუსტად იგივე ნორმალიზებული ტელეფონი/ელფოსტა, ტრანზიტიულადაც. **მხოლოდ მსგავსი სახელები არ აერთიანებს ჩანაწერებს.** სხვადასხვა დომენზე საერთო კონტაქტის გამო გაერთიანება მოითხოვს გადამოწმებას — შესაძლოა საერთო ოფისი ან ჯგუფი იყოს. `merged` ცვლილება ინახავს შთანთქმული ჩანაწერის ID-სა და დარჩენილ ID-ს.

ახალი მნიშვნელობები ემატება ისტორიას. **არც ქსელური შეცდომა, არც ცარიელი პასუხი და არც წარმატებულ გვერდზე ძველი კონტაქტის არყოფნა ავტომატურად არ შლის მას.** `last_seen` არის ბოლო რეალური ნახვის დრო; გაშვების თარიღთან განსხვავებული დრო შეიძლება ძველ მნიშვნელობაზე მიუთითებდეს. მხოლოდ დროის/წყაროს განახლება `changed` არ არის; სახელის, კონტაქტის, დომენის ან გადასამოწმებელი მიზეზის ცვლილება არის. ძველი review მიზეზებიც შენარჩუნდება ადამიანის გადამოწმებამდე. ამიტომ გამოცვლილი ნომერიც შეიძლება ძველთან ერთად დარჩეს — კონტაქტების ავტომატურ წაშლაზე განზრახ უპირატესობა ენიჭება მონაცემის შენარჩუნებას.

## მდგომარეობა და GitHub Actions

`Collect public contacts` მუშაობს `ubuntu-latest`-ზე, 30-წუთიანი job ზღვარით. შეგროვებას აქვს ნაგულისხმევი 24-წუთიანი რბილი ბიუჯეტი, რათა დარჩეს დრო state-ის push-სა და artifact-ზე. ლოკალურადაც 30-წუთიანი hard alarm არის. დროულ შეჩერებაზე შედეგები `time_limit_partial`-ით ინახება და დაბრუნდება კოდი 2; workflow-ის `always()` ნაბიჯები ნაწილობრივ checkpoint-საც აქვეყნებს. Runner-ის მკვეთრი გაუქმების/30-წუთიანი hard timeout-ისას ბოლო ლოკალური checkpoint-ის ატვირთვა გარანტირებული ვერ იქნება.

- ყველა შეგროვების გაშვება იზიარებს `contacts-data-branch` concurrency ჯგუფს; `cancel-in-progress: false` მიმდინარე გაშვებას არ წყვეტს. GitHub-ს შეუძლია ზედმეტი pending გაშვების ჩანაცვლება; ეს დაუსრულებელი რიგის გარანტია არ არის.
- სამუშაოს დასაწყისში იტვირთება მხოლოდ `data` ბრენჩის მდგომარეობა. არსებული ბრენჩის გაუმართავი/დაკარგული state არ იცვლება ცარიელი ბაზით.
- `data` არის ცალკე orphan ისტორია; მასში მხოლოდ state და ექსპორტები ინახება, workflow-ები არა. push ჩვეულებრივია, `--force` არ გამოიყენება. გარე ერთდროული ცვლილება push-ს უსაფრთხოდ ჩააგდებს; artifact დარჩება ხელმისაწვდომი.
- scraper-ს push trigger საერთოდ არ აქვს. ოფლაინ CI მხოლოდ `main`-ის push/PR-ზე მუშაობს. `data` ცვლილებები არ წარმოქმნის ციკლს; commit-ს დამატებით აქვს `[skip ci]`.
- CI მხოლოდ `contents: read`-ს იღებს. შეგროვების job-ს სჭირდება `contents: write` მხოლოდ snapshot-ისთვის. Actions მითითებულია commit SHA-ებით; გარე კოდი main-ზე მხოლოდ ავტორიზებულ ცვლილებებში უნდა მოხვდეს.

მფლობელის მოთხოვნით ჩართულია **წყაროების ამოწურვამდე ავტომატური გაგრძელება**. `scrape.yml`-ის ხელით გაშვებაზე `continuous: true` იწყებს/აგრძელებს კამპანიას; პარტიის ბოლოს თავად სამუშაო ჩაშენებული `GITHUB_TOKEN`-ით მომდევნო `workflow_dispatch`-ს ითხოვს. `continue.yml`-ის 30-წუთიანი watchdog მხოლოდ დაუმთავრებელ, უმოქმედო კამპანიას განაახლებს. კვირეული სრული ხელახალი გადამოწმება გამორთული რჩება.

```bash
gh workflow run scrape.yml --ref main -f limit=1000 -f sources=config/sources.json -f continuous=true -f restart=false
```

`--limit` მხოლოდ ერთი პარტიის ზომაა. კონტაქტების საერთო რაოდენობას და კამპანიის გაგრძელებას 1000-იანი ჭერი **არ აქვს**. შემდეგი პარტია დარჩენილი რიგიდან მუშაობს, უკვე დასრულებულ წყაროებს აღარ იწყებს თავიდან. ახალი ნაპოვნი საიტები რიგში ემატება; შეცვლილი ფაქტების მქონე კანდიდატიც ხელახლა მოწმდება. დროებითი ქსელური/პარსერის შეცდომა მაქსიმუმ სამ პარტიაში მოწმდება, შემდეგ მიუწვდომლად ინიშნება. 429-ის Retry-After პაუზა ინახება მდგომარეობაში და შემდეგ პარტიებშიც სრულდება. თუ ყველა დარჩენილი წყარო პაუზაშია, ანგარიში waiting-ს აჩვენებს და watchdog პაუზის შემდეგ განაახლებს. აკრძალული/ავტორიზებული/CAPTCHA/JS წყაროს გვერდის ავლა არ ხდება. ბოლო ანგარიში აჩვენებს დარჩენილ ბიზნესებსა და კატალოგის გვერდებს.

თითო პარტიას ისევ 24-წუთიანი რბილი და 30-წუთიანი მკაცრი ზღვარი აქვს. Actions-ში ადგილობრივი checkpoint-ები დაახლოებით 120 წამში ერთხელ data ბრენჩზეც აიტვირთება, საბოლოო შენახვის დამატებით. snapshot-ის საჯარო ისტორია ბოლო ხუთი შეგროვების მდგომარეობას შეიცავს. data-ს `vercel.json` გამორთავს მხოლოდ data ბრენჩის ვებგანთავსებას; main-ის ვებსაიტი ჩვეულებრივ განახლდება.

თუ ხელმისაწვდომი სამუშაო აღარ დარჩა, `collection_status: exhausted` და `work_remaining: false` მომდევნო პარტიას აჩერებს. ეს ნიშნავს **კონფიგურირებულ, ნებადართულ წყაროებს**, არა მთელ ქართულ ინტერნეტს. სამი უშედეგო პარტია `paused / no_progress_requires_review` მიზეზით აჩერებს გაუთავებელ წრეს. ეს ამოწურვად არ ითვლება; დარჩენილი სამუშაო ანგარიშში ჩანს. სამი კრიტიკული failure ახალი checkpoint-ის გარეშე ასევე მოითხოვს ხელით შეკეთებას. ბოლო გაშვების GitHub-ზე Cancel ავტომატურ გაგრძელებას აჩერებს, სანამ ხელით ახალ გაშვებას არ დაიწყებ.

ახალი სრული გადამოწმებისთვის, ძველი კონტაქტების წაშლის გარეშე:

```bash
gh workflow run scrape.yml --ref main -f limit=1000 -f sources=config/sources.json -f continuous=true -f restart=true
python -m georgia_contacts.cli --continuous --sources config/sources.json --limit 1000
```

ლოკალური CLI მხოლოდ ერთ პარტიას აკეთებს; ავტომატურ ჯაჭვს GitHub workflow მართავს. ლოკალური სრული თავიდან დაწყებისთვის დაუმატე `--restart-campaign`. ერთჯერადი GitHub გაშვებისთვის აირჩიე `continuous: false`. controller-ის შეჩერება: Actions → Continue unfinished collection → Disable workflow; საჭიროებისას მიმდინარე Collect public contacts გაშვებაც გააუქმე.

გაშვებების რიგს და scheduled watchdog-ს GitHub შესაძლოა აგვიანებდეს, ამიტომ ეს მუდმივი სერვერის შეუფერხებელი 24/7 მუშაობის გარანტია არ არის. [GitHub workflow dispatch](https://github.blog/changelog/2022-09-08-github-actions-use-github_token-with-workflow_dispatch-and-repository_dispatch/) და [განრიგის შეზღუდვები](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

უფასო ბიბლიოთეკები არ ნიშნავს შეუზღუდავ ჰოსტინგს: GitHub Actions-ის უფასო შესრულება/საცავი ექვემდებარება ანგარიშის გეგმას, საჯარო რეპოზიტორიისა და სტანდარტული runner-ის მიმდინარე წესებს, გამოყენების ლიმიტებსა და მათ ცვლილებებს. იხილეთ [მოქმედი ლიმიტები](https://docs.github.com/en/actions/reference/limits). ფასიანი runner ან გარე სერვისი ამ პროექტში ჩართული არ არის.

## ვებსაიტის პოტენციური კლიენტები — ცალკე გვერდი

`/leads/` დამოუკიდებელი B2B გვერდია. აირჩიე კატეგორია, ქალაქი და მიზანი, შემდეგ „მოძებნა“. შედეგებში ჩანს ბიზნესის საჯარო ტელეფონი/ელფოსტა, სოციალური ბმულები, შემოწმებული წყარო და თარიღი. CSV/JSON ღილაკები **გაფილტრულ შედეგებს** ჩამოტვირთავს; CSV შეიცავს UTF-8 BOM-ს და ფორმულის ინექციისგან დაცვას.

შეგროვება ცალკე GitHub Actions პროცესში სრულდება, გვერდი კი ყოველ 90 წამში შენახულ შედეგებს აახლებს. „მოძებნა“ ბაზას ფილტრავს; ბრაუზერიდან თვითნებურ ინტერნეტძიებას ან ახალი კატეგორიის ავტომატურ აღმოჩენას არ აკეთებს. გვერდის ნახვასა და ძიებას ტოკენი არ სჭირდება. კატეგორიების დამატებას წყაროს წინასწარი შემოწმება სჭირდება.

**საიტი წყაროში არ არის მითითებული ≠ ბიზნესს საერთოდ არ აქვს საიტი.** ეს გაყიდვის კანდიდატია და გადასამოწმებელია. ცალკე აღირიცხება სოციალური ბმულის არსებობა, დაუზუსტებელი ვებსაიტის ბმული და მითითებული საიტის შემოწმება. დროებითი ქსელური შეცდომა საიტის არყოფნად არ ითვლება. ბიზნესის დომენიანი ელფოსტა მხოლოდ დამატებითი მინიშნებაა; მისგან ვებსაიტი არ გამოიგონება. კოდი შეტყობინებებს არ აგზავნის და პირად პროფილებს/კომენტარებს არ აგროვებს.


წყაროები: `config/leads-sources.json`; Python: `georgia_leads/`; ლოკალური მდგომარეობა: `.leads-state/state.json`; შედეგები: `output/leads/`; საჯარო მონაცემები: **`leads-data` ბრენჩი**. ინტერიერის `data` ბრენჩი, `.state/` და მისი workflow უცვლელი პროცესია. კოდი სხვა pipeline-ის მდგომარეობას არ იღებს. ახალ workflow-ს საკუთარი concurrency ჯგუფი აქვს; data push არც მთავარ workflow-ს რთავს და არც Vercel deployment-ს.

GitHub → Actions → **Collect website prospects** → Run workflow: წყარო `config/leads-sources.json`, `continuous=true`. ხელით გაშვების საწყისი ლიმიტი 50-ია; ეს ერთი ეტაპის ლიმიტია. გაგრძელებები დარჩენილ გვერდებსა და ბიზნესებს დამოუკიდებლად ამუშავებს, კონტაქტები ემატება ეტაპობრივად. თითო გაშვებას აქვს 30-წუთიანი ზღვარი, 24-წუთიანი პროგრამული ვადა და 120-წამიანი გამოქვეყნება. ჩამოსატვირთი artifact: `website-prospects-…`, შენახვა 7 დღე. გამოყენებულია ჩაშენებული `GITHUB_TOKEN`; პირადი ტოკენი შედეგებსა და საჯარო კოდში არ ხვდება.

### ავტომატური გაგრძელება და გაჩერების შეტყობინება

ინტერიერის შეგროვება დასრულებული ეტაპის შემდეგ ავტომატურად აგრძელებს დარჩენილ სამუშაოს. დამოუკიდებელი კონტროლი გაწერილია საათის 07, 22, 37 და 52 წუთებზე და ამოწმებს, ხომ არ დარჩა გასაგრძელებელი ეტაპი. უკვე გაშვებულ/რიგში მდგომ პროცესს არ აორმაგებს. ეს დღე-ღამის განმავლობაში მოქმედი ავტომატიზაციაა; GitHub Actions-ის განრიგის შესრულება შეიძლება დაგვიანდეს ([GitHub-ის განრიგის წესები](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)), ამიტომ წამებში უწყვეტი მუშაობა გარანტირებული არ არის.
