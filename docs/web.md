# ვებპანელი და Vercel

მარტივი პანელი: კონტაქტების ძიება, ფილტრები, CSV/JSON ჩამოტვირთვა, შეგროვების დაწყება და გაშვებების მდგომარეობა. თავად სკრაპერი GitHub Actions-ზე მუშაობს; Vercel მხოლოდ მოკლე გაშვების მოთხოვნას აგზავნის.

## ლოკალურად

Node.js 22+, გარე JavaScript ბიბლიოთეკების გარეშე:

```bash
npm run dev
npm test
npm run build
```

პანელი: http://127.0.0.1:4173. საიტის გახსნა შეგროვებას ავტომატურად არ იწყებს.

## საჯარო მონაცემები

ბაზა არის `kapana22/georgia-interior-contacts` რეპოზიტორიის `data` ბრენჩზე. `snapshot.json` ერთ ფაილში ინახავს კონტაქტებსა და შესაბამის ანგარიშს. პანელი მას პირდაპირ `raw.githubusercontent.com`-დან კითხულობს: არ მიმართავს ანონიმურ GitHub API-ს, არ სჭირდება ტოკენი და არ ხარჯავს API-ს საათობრივ 60 მოთხოვნის ლიმიტს.

ხილულ გვერდზე მონაცემები 90 წამში ერთხელ განახლდება; GitHub-ის CDN-ის ქეშის გამო ახალი commit შეიძლება მაშინვე არ გამოჩნდეს. წარუმატებელი განახლება უკვე ჩატვირთულ სიას არ შლის. CSV/JSON ღილაკები `data` ბრენჩის ბოლო საჯარო ფაილებს ჩამოტვირთავს; მიმდინარე ეკრანის ფილტრები ექსპორტს არ ზღუდავს. ექსპორტი შეიძლება ეკრანზე ნაჩვენებზე ახალი გაშვების იყოს. CSV ინარჩუნებს UTF-8 BOM-ს და ფორმულის ინექციისგან დაცვას.

საჯარო რეპოზიტორიაში **მონაცემებიც საჯაროა**. წყარო და შეგროვების თარიღი თითოეულ კონტაქტს ახლავს. გადასამოწმებელ ჩანაწერებს მიზეზები აქვს. სამიზნე 1000 არის მიზანი და არ ნიშნავს, რომ ბაზაში უკვე 1000 დადასტურებული კონტაქტია.

## Vercel

პროექტის Settings → Build:

- Root Directory: რეპოზიტორიის ძირი; Framework: Other.
- Build Command: `npm run build`; Output Directory: `web/dist`.
- Production Branch: `main`; Install Command: ცარიელი.

ალტერნატიული ძირი `web` ასევე მხარდაჭერილია: Output `dist`, იმავე საქაღალდის `api/collector.mjs` და `vercel.json`.

`web/dist` შეიცავს მხოლოდ ხუთ საჯარო ვებფაილს. `api/collector.mjs` ცალკე სერვერული ფუნქციაა. Python CLI ვებსერვერის entrypoint არ არის; Other პარამეტრი ასწორებს „No python entrypoint found“ შეცდომას.

## ავტორიზაციის გარეშე გაშვება

მფლობელმა Vercel-ის **ამ პროექტის** Settings → Environment Variables-ში ერთხელ უნდა დაამატოს:

- Name: `GITHUB_ACTIONS_TOKEN`.
- Value: მხოლოდ ამ რეპოზიტორიაზე შეზღუდული fine-grained GitHub PAT; Actions: Read and write.
- Environment: Production (Preview მხოლოდ თუ იქაც საჯარო გაშვება გჭირდება).

შემდეგ გაუშვი ახალი production deployment. ტოკენი სერვერზე რჩება; არ გამოიყენო `NEXT_PUBLIC_`/`VITE_` პრეფიქსი, არ ჩაწერო კოდში, საჯარო ფაილში ან ჩატში. საჯარო სტუმარს ტოკენის ჩასმა აღარ სჭირდება. ეს განსხვავდება მფლობელის ბრაუზერში დამახსოვრებული ტოკენისგან: მხოლოდ ბრაუზერის დამახსოვრება სხვა სტუმარს გაშვების უფლებას ვერ მისცემს.

Endpoint იღებს მხოლოდ ფიქსირებული რეპოზიტორიის `scrape.yml` workflow-ს გაშვებას main-ზე, ლიმიტით 1–1000 და `config/sources.json` ან `config/smoke.json`. თვითნებურ URL-ს, GitHub endpoint-ს ან ფაილის ჩაწერას ვერ მიიღებს. გაშვებების სია სერვერზე 15 წამით ქეშდება. უკვე მიმდინარე/რიგში მყოფი სამუშაო ხელახლა არ იგზავნება. ერთი პროცესის განმეორებითი მოთხოვნა ერთი წუთით იზღუდება; სხვადასხვა სერვერულ პროცესს შორის ეს ლიმიტი სრული საერთო rate limiter არ არის. GitHub workflow concurrency პარალელურ შეგროვებას გამორიცხავს, თუმცა ერთდროულ საჯარო მოთხოვნებს რიგში მეორე გაშვების ჩასმა მაინც შეუძლია. საჯარო გაშვებები ხარჯავს GitHub/Vercel-ის მოქმედ უფასო ლიმიტებს.

POST მოთხოვნა ავტომატურად არ მეორდება. დროებითი ქსელის შეცდომის შემდეგ გამეორებამდე გაშვებები გადაამოწმე. გვერდის დახურვა GitHub-ზე მიმდინარე სკრაპინგს არ აჩერებს. თუ სერვერული ტოკენი არ არის გამართული, ნახვა მაინც მუშაობს; გაშვება აჩვენებს შესაბამის მიზეზს. მფლობელს ბრაუზერის ავტორიზაციით ან GitHub-ის Run workflow ფორმიდან გაშვება კვლავ შეუძლია.

ლოკალურ სერვერს იგივე endpoint აქვს; გაშვებისთვის გარემოში `GITHUB_ACTIONS_TOKEN` უნდა იყოს არსებული უსაფრთხო საცავიდან მოწოდებული. `.env` ფაილები gitignore-შია, მაგრამ dev სერვერი მათ ავტომატურად არ კითხულობს.

## წყაროების რედაქტირება

სია საჯაროდ იკითხება პირდაპირ raw ფაილიდან. რედაქტირება მფლობელის ავტორიზაციას მოითხოვს: fine-grained PAT, Contents: Read and write მხოლოდ ამ რეპოზიტორიაზე. ეს ცვლის საჯარო `config/sources.json`-ს main commit-ით, SHA კონფლიქტის შემოწმებით. ახალი წყაროს კონტაქტები გამოჩნდება შემდეგ შეგროვებაზე. გამორთვა ძველ კონტაქტებს არ შლის.

„დამიმახსოვრე ამ ბრაუზერში“ ინახავს მფლობელის PAT-ს ამ origin-ის localStorage-ში; სხვა დომენზე/მოწყობილობაზე არ გადადის და დაშიფრული პაროლების საცავი არ არის. „გათიშვა“ შლის შენახულ ტოკენს. იგი მხოლოდ api.github.com-ს ეგზავნება. საჯარო სტუმრებს წყაროების ჩაწერის ან სერვერული PAT-ის მიღების უფლება არ აქვთ.

## შემოწმება

78 Python და 27 JavaScript ოფლაინ ტესტი: კონტაქტები, მდგომარეობის შენარჩუნება, გაერთიანება, საჯარო სერვერის პარამეტრები/ტოკენის გაუმჟღავნებლობა, აქტიური სამუშაოს ხელახალი გამოყენება და dispatch-ის არგამეორება. მიმდინარე ცოცხალი შემოწმების შედეგები: `docs/VALIDATION.md`.

ოფიციალური ინსტრუქციები: [Vercel Node functions](https://vercel.com/docs/functions/runtimes/node-js), [Environment variables](https://vercel.com/docs/environment-variables), [GitHub workflow dispatch](https://docs.github.com/en/rest/actions/workflows#create-a-workflow-dispatch-event).

## განახლებული მარტივი მართვა

ძირითად ეკრანზე არის ძიება, ქალაქის/შესაბამისობის/კონტაქტის ტიპის ფილტრები, კოპირება, ჩამოტვირთვა და გვერდის ზომა. ფორმატირებული ტელეფონი (ფრჩხილებით, გამოტოვებებით, დეფისებით) ასევე იძებნება. Ctrl/Cmd+K ძიებას ააქტიურებს. ძიების ფილტრები ერთი ღილაკით იწმინდება.

რიცხვებით პარტიის არჩევანი მთავარ ეკრანზე აღარ არის. ვებგაშვება ითხოვს 1000 ბიზნესის პარტიას და default continuous რეჟიმს; მთელი ბაზის ზომაზე ეს ჭერი არ ვრცელდება. GitHub-ის ავტომატური კამპანია Vercel სერვერული ტოკენის გარეშეც მუშაობს. სტატუსი და ბოლო ხუთი შეგროვება პირდაპირ საჯარო snapshot-იდან ჩანს. GitHub Actions-ის სრული job ისტორია და CLI-ის checkpoint-ების ისტორია სხვადასხვა ცნებაა: snapshot-ის დასრულება ნიშნავს CLI პარტიის დასრულებას, artifact-ის ატვირთვა შეიძლება ჯერ სრულდებოდეს.

როდესაც Vercel-ზე GITHUB_ACTIONS_TOKEN არ არის გამართული და მფლობელიც არ არის დაკავშირებული, არამუშა ხელით გაშვების ფორმა იმალება. რჩება ავტომატური კამპანიის საჯარო მდგომარეობა და GitHub-ზე მართვის ბმული. საიტიდან საჯარო ხელით გაშვების დასაკავშირებლად ჯერ ისევ საჭიროა მფლობელის Vercel პროექტში მხოლოდ სერვერული token-ის ერთხელ დამატება; ის არ ქვეყნდება და GitHub ავტომატურ გაგრძელებას არ სჭირდება.
