# ვებპანელი და Vercel

ვებპანელი არის `web/` საქაღალდეში. ინტერფეისი მარტივია: ბიზნესების ლიმიტი, წყაროების ფაილი, შეგროვების დაწყება, გაშვების მდგომარეობა, კონტაქტების ძიება/ქალაქით/სტატუსით გაფილტვრა, წყაროების დამატება/რედაქტირება/გამორთვა და ექსპორტის ჩამოტვირთვა.

ვებსაიტი სტატიკურია. **შეგროვება ისევ GitHub Actions-ზე მუშაობს** — Vercel-ის მოთხოვნა 30 წუთით არ იკავებს ფუნქციას. გვერდის გახსნა შეგროვებას არ იწყებს. საიტს ფასიანი სერვისი, ბექენდი, მონაცემთა ბაზა ან Vercel Secrets არ სჭირდება.

## ლოკალურად

საჭიროა Node.js 22+; JavaScript ნაწილს გარე დამოკიდებულებები არ აქვს.

```bash
npm run dev
```

გახსენი **http://127.0.0.1:4173**. შეჩერება: Ctrl+C. ტესტები და build:

```bash
npm test
npm run build
```

წარმოიქმნება `web/dist/`: მხოლოდ ხუთი საჯარო ფაილი — HTML, CSS, ორი JS მოდული და favicon. პროექტის Python კოდი, state, ტესტები, `.env` და Git მონაცემები ვებსაიტთან ერთად არ ქვეყნდება.

## Vercel-ზე არსებული „No python entrypoint found“ შეცდომა

პირველი განთავსება დაეყრდნო მხოლოდ Python სკრაპერის ძველ commit-ს. Vercel-მა Python ვებაპის entrypoint მოძებნა, თუმცა სკრაპერი CLI პროგრამაა. ახალი ვერსია შეიცავს ვებსაიტს, `package.json`-სა და `vercel.json`-ს, სადაც `framework: null` ნიშნავს **Other**-ს.

იგივე რეპოზიტორიის `main`-ზე ახალი commit-ის მიღების შემდეგ:

1. გახსენი შენი Vercel პროექტი **georgia-interior-contacts** → **Settings**.
2. **Root Directory** დატოვე რეპოზიტორიის ძირი (`./` ან ცარიელი ველი).
3. **Framework Preset**: **Other**.
4. **Build Command**: `npm run build`.
5. **Output Directory**: `web/dist`.
6. **Install Command** ცარიელია — დამოკიდებულებები არ არის. `vercel.json` ამასაც ადგენს.
7. **Production Branch**: `main`.
8. შენახვის შემდეგ გაუშვი **Redeploy ახალი commit-ისთვის**. ძველი `8553289` commit-ის Redeploy ვებფაილებს ვერ დაამატებს.

თუ Root Directory-ად `web` გირჩევნია, გამოიყენე ამ საქაღალდის საკუთარი `vercel.json`: **Other**, Build `npm run build`, Output `dist`. პარამეტრები არ აურიო: ძირი `./` → `web/dist`; ძირი `web` → `dist`.

კონფიგურაციის ოფიციალური წყაროები: [Vercel Build settings](https://vercel.com/docs/builds/configure-a-build), [vercel.json](https://vercel.com/docs/project-configuration/vercel-json). Vercel-ზე საიტს მომხმარებელი ათავსებს თავისი ანგარიშიდან.

## ნახვა და ჩამოტვირთვა

შედეგების ნახვას ავტორიზაცია არ სჭირდება. პანელი `data` ბრენჩის commit-ს კითხულობს და ამ **ერთი ვერსიიდან** ტვირთავს JSON-სა და ანგარიშს, რათა სხვადასხვა გაშვების ფაილები არ აირიოს. CSV/JSON ღილაკები ამავე შენახულ ვერსიას ჩამოტვირთავს.

ფილტრები ეკრანზე ხილულ სიას ცვლის; CSV/JSON **მთელ შენახულ ბაზას** ჩამოტვირთავს. `···` მენიუში არის changes.csv, report.txt და report.json. CSV პირდაპირ სკრაპერის შენახული ბაიტებით ჩამოდის — UTF-8 BOM და ფორმულებისგან დაცვა შენარჩუნებულია.

გვერდზე „კანდიდატი“ არის ავტომატური შესაბამისობის შედეგი. გადასამოწმებელ ჩანაწერში შეგიძლია ნახო მიზეზები, თითო კონტაქტის წყარო და თარიღი. საჯარო რეპოზიტორიაში მონაცემებიც საჯაროა.

## პირდაპირი გაშვება და წყაროების მართვა

მხოლოდ შენ ან რეპოზიტორიაზე შესაბამისი უფლებების მქონე მომხმარებელი შეძლებს ცვლილებებს. ამისთვის დააჭირე **ავტორიზაციას** და გამოიყენე მხოლოდ ამ რეპოზიტორიაზე შეზღუდული **Fine-grained personal access token**:

- Resource owner: **kapana22**.
- Repository access: მხოლოდ **georgia-interior-contacts**.
- Repository permissions → **Actions: Read and write** — workflow-ს გასაშვებად.
- წყაროების შენახვისთვის დამატებით **Contents: Read and write**.

შექმნის გვერდი: [GitHub tokens](https://github.com/settings/personal-access-tokens/new). არ ჩაწერო ტოკენი კოდში, GitHub commit-ში, Vercel Environment Variables-ში ან ჩატში. მხოლოდ თვითონ ჩასვი პანელის პაროლის ველში.

ტოკენი ინახება მხოლოდ JavaScript-ის კერძო მეხსიერებაში; localStorage/sessionStorage/cookie-ს არ იყენებს. პაროლის ველი ავტორიზაციის მცდელობისას იწმინდება. ტოკენი უშუალოდ **api.github.com**-ს გაეგზავნება, Authorization header-ით, გადამისამართების აკრძალვით. იგი Vercel-ის სერვერს, raw.githubusercontent.com-სა და ბიზნესის საიტებს არ გაეგზავნება. გვერდის დახურვა/განახლება ან „გათიშვა“ კავშირს შლის.

პირდაპირი workflow dispatch-ისთვის GitHub-ს ავტორიზაცია სჭირდება; ჩაშენებული `GITHUB_TOKEN` მხოლოდ workflow-ის შიგნით არსებობს და საჯარო ვებგვერდში ვერ განთავსდება. სკრაპერის GitHub Actions პროცესი კვლავ მხოლოდ ჩაშენებულ `GITHUB_TOKEN`-ს იყენებს. [GitHub dispatch უფლებები](https://docs.github.com/en/rest/actions/workflows#create-a-workflow-dispatch-event).

ტოკენის გარეშე შეგროვება შეგიძლია დაიწყო **„GitHub-იდან“** ბმულით, GitHub-ის საკუთარ Run workflow ფორმაში. იქ ლიმიტი და ფაილის გზა ცალკე მიუთითე; პანელის პარამეტრები იმ ფორმაში ავტომატურად არ გადაიტანება.

გაშვების შემდეგ ფორმა ზუსტ run ID-ს იყენებს, თუ GitHub-მა დააბრუნა; იგი სტატუსს 15 წამში ერთხელ ამოწმებს, მხოლოდ აქტიური გაშვებისას და ხილულ გვერდზე. POST მოთხოვნა ავტომატურად არ მეორდება: კავშირის გაწყვეტისას ხელახლა გაშვებამდე GitHub-ზე გადამოწმება შეიძლება საჭირო იყოს. გვერდის დახურვა მიმდინარე სკრაპინგს არ აჩერებს.

წყაროების მართვა ცვლის მხოლოდ ძირითად `config/sources.json`-ს. დამატება/რედაქტირება/გამორთვა ინახება საჯარო main commit-ად. თუ შენს Vercel პროექტს Git ინტეგრაცია აქვს, ასეთ commit-ს ახალი build შეიძლება მოჰყვეს. კონტაქტები განახლდება **შემდეგ შეგროვებაზე**, არა წყაროს შენახვისთანავე. `config/smoke.json` და კატალოგის პარამეტრები რეპოზიტორიიდან რედაქტირდება.

ახალი ან შეცვლილი URL თავიდან გადასამოწმებლად ინიშნება. გამორთვა ძველ კონტაქტებს არ შლის. დომენის დუბლიკატები და სხვა დომენის საკონტაქტო გვერდები ფორმაში უარყოფილია. შენახვას აქვს GitHub ფაილის SHA-ის შემოწმება: თუ ამასობაში სხვამ შეცვალა ფაილი, 409 კონფლიქტი ცარიელი/ძველი ვერსიით არ გადაწერს მას. სია თავიდან გახსენი და ცვლილება გაიმეორე. GitHub branch protection-ს თუ პირდაპირი commit აკრძალული აქვს, წყარო GitHub PR-ით შეცვალე.

## შემოწმება

- 15 ოფლაინ JavaScript ტესტი: ლიმიტები, ბილიკები, ქართული ძიება, ბმულების უსაფრთხოება, ტოკენის scope/წაშლა, dispatch, POST-ის არგამეორება, source ფაილის SHA კონფლიქტი და UTF-8 base64.
- Python-ის 68 ტესტი; ვებპანელის 17 ოფლაინ ტესტი.
- Chrome-ში რეალური საჯარო ბაზის ჩატვირთვა: 4 ბიზნესი/15 კონტაქტი; სახელით ძიება, review ფილტრი, 11 წყაროს ფანჯარა და CSV-ის ჩამოტვირთვა/UTF-8 BOM შემოწმდა.
- Github API-ზე რეალური token-ით ვებფორმის dispatch ან source PUT არ შესრულებულა: ეს ქმედებები mocked HTTP პასუხებით შემოწმდა. პანელი რეპოზიტორიაში სატესტო ბიზნესებს არ ამატებს.
- Vercel-ის ახალი განთავსების წარმატება ლოკალური build-ით ვერ დამტკიცდება; გადაამოწმე შენს ანგარიშზე ახალი commit-ის deployment-ის შედეგი.

მფლობელის არჩევანით Expiration შეიძლება იყოს **No expiration**. ტოკენი მაინც მხოლოდ ბრაუზერის მეხსიერებაში რჩება: გვერდის განახლების შემდეგ ხელახლა უნდა ჩასვათ; ვადა და ლოკალური შენახვა სხვადასხვა რამეა. ახალი წვდომის შექმნის საბოლოო ღილაკს მფლობელი აჭერს.

საჯარო `data` ბრენჩის ახალი SHA ხილულ პანელში 90 წამში ერთხელ მოწმდება; უცვლელი ვერსიის ფაილები ხელახლა არ იტვირთება. ფოკუსზე დაბრუნებისას ძველი მონაცემი განახლდება. ეს შეგროვების დაწყება არ არის. `კონტაქტები` სიის რიცხვი ბიზნესის ჩანაწერებს ითვლის; ტელეფონი/ელფოსტა ზედა მთვლელში ცალკეა.
